# Стек и структура

Версии инструментов закреплены в корневом `rokit.toml`: Rojo 7.7.0, Wally 0.3.2, StyLua 2.5.2, Selene 0.31.0, Lune 0.8.9, luau-lsp 1.70.1. Библиотеки React/ReactRoblox 17.2.1 и Ripple 0.10.2 закреплены в `RojoTest/wally.toml` и `wally.lock`.

## Исходники

`RojoTest/src/shared/` содержит конфигурацию, визуальные помощники, сетевые контракты `Net` и чистые модули `Core/ProfileData` и `Core/Economy`. `src/server/Services/` содержит ProfileService и WorldService, `src/server/Gameplay/` — разбиение игрового скрипта на сессию, бросок, тренировку, команды, чеки, промпты, снапшот и жизненный цикл. `src/client/Controllers/` и `src/client/Modules/` содержат HUD, панели, питомцев, ввод, звук, мир и раскладку.

Единый стиль интерфейса лежит в `src/client/UiStyle.luau`: палитра, скругления, толщины обводок, текстура кирпича и числа пружин. React-слой читает его через `CollectorUI/Theme.luau`, legacy-слой — напрямую (`HudKit.luau`, `HudPanels.luau`, `AdminPanel.luau`). Описание стиля для человека — в `docs/ui-style.md`.

Сервер сначала вызывает Init всех сервисов, затем Start. WorldService использует существующие идемпотентные процедуры оформления сцены; SkippingGame сохраняет текущие механики. Клиентский bootstrap аналогично запускает GameplayController с существующими HUD, камерой и React-экранами. Knit и автоматический поиск сервисов не используются.

`Core/Economy` не зависит от Roblox API: уровни, пороги, кривая перерождений, дальность броска, выбор питомца и форматирование чисел вынесены туда и покрыты Lune-тестами.

ProfileStore хранится без модификаций в `src/serverPackages/` и попадает только в `ServerStorage.ServerPackages`. Настоящая библиотека, её лицензия, commit и SHA-256 включены в проект. Клиентам профили и чеки не передаются.

## Сеть

`Net` создаёт в `ReplicatedStorage` три удалённых объекта: `Action`, `Update` и `Effect` — RemoteEvent. `Admin` — RemoteFunction — сервер создаёт лениво, только когда в игру заходит авторизованный игрок. `Net.validAction` — единственное место, где проверяется форма клиентской команды.

Payload `Update` разделён на две части. `data` несёт прогресс, который меняется каждый тик. `inventory` несёт список питомцев и экипированные слоты и отправляется только когда инвентарь изменился: шестьдесят питомцев больше не передаются два с половиной раза в секунду. Клиент хранит последний известный инвентарь и принимает свежий, как только payload его приносит.

## Ассеты и репозиторий

Rojo разрешает синхронизацию только с place `106456161057435`. Порт по умолчанию — `34872`. Ручные Workspace-объекты и Lighting не управляются project mapping. Шаблоны ассетов и исходники синхронизируются по явно указанным путям. Открытую авторскую сцену необходимо сохранять средствами Studio; standalone build не содержит всех ручных изменений сцены.

Дерево `RojoTest/Packages/` генерируется `wally install` и не версионируется: его правка на месте оставляла сотни изменённых вендорных файлов в `git status`. Бинарные ассеты (`.blend`, `.fbx`, `.png`, `.zip`) хранятся в Git LFS, XML и JSON остаются обычным текстом. В репозитории также лежат библиотека ProfileStore и все рабочие скрипты — раньше они в Git не попадали.

`StartRojo.bat` и `StopRojo.bat` вызывают `RojoTest/tools/rojo.ps1`. Запуск скрытый, адрес loopback, журнал и запись процессов находятся в `.tools/`. Повторный запуск переиспользует сервер своего проекта. Занятый чужим процессом порт вызывает ошибку. Остановка проверяет путь проекта, PID, путь бинарника и время запуска; чужие Rojo-процессы не завершаются.

## Проверка

`node RojoTest/tools/check.mjs` — полный гейт. Шаги: установка зависимостей Wally (только если дерево `Packages/_Index` расходится с `wally.lock`), подготовка alias'ов Ripple через `tools/prepare-ui.mjs`, сверка `Packages/_Index` с `wally.lock`, StyLua, Selene (отдельно для `src` и для `tools`), Lune-тесты, сборка Rojo, sourcemap Rojo и проверка типов Luau.

Проверка типов использует `luau-lsp analyze` со снимком типов Roblox (`tools/fetch-luau-types.mjs`, версия и SHA-256 закреплены) и sourcemap Rojo. Известные находки лежат в `tools/typecheck-baseline.txt`; гейт падает только на новых. Ключ baseline не содержит номеров строк и текста выведенных типов, поэтому вставка строки или перестановка полей не выглядит новой находкой.

`roblox.yml` — локальный снимок Roblox API для воспроизводимого офлайн-линтинга; обновлять его следует отдельно с проверкой диффа.

Полный набор запускается и в CI: `.github/workflows/checks.yml` собирает проект на чистой машине с `rokit install` и `node RojoTest/tools/check.mjs`. Selene и сборка не заменяют полноценную проверку типов Luau и Studio Play.
