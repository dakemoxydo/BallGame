## 1. CRITICAL

### A1. Залипающий `ModalBlocker` в CollectorUI намертво блокировал весь интерфейс игры

- **Где:** `RojoTest/src/client/CollectorUI/init.luau` (`Window`, `App`, `handle:close`)

**Механика.** `handle.View` очищался только в колбэке `Settled`, а `Settled` вызывался только из
`onComplete` пружины Ripple. Ripple **не стреляет `onComplete`, если цель пружины не изменилась**
(`ripple/src/spring.luau:330`: `if intermediate.setValue(self.state.goal, value) then
self:scheduleUpdate() end`). Замерено в Studio: пружина с целью 0 из начального 0 даёт
`onComplete=false`, `onChange=0`.

Окно `Window` монтируется с `Visible = handle.Active ~= nil`. Если окно монтировалось **уже
закрытым**, цель была 0 → 0, анимации не было, `Settled` не вызывался, и `handle.View` оставался
не-nil навсегда. Дальше:

- `navVisible` требует `view == nil or handle.Active ~= nil` → **навигация исчезала навсегда**;
- полноэкранный `ModalBlocker` (`TextButton`, `Modal = true`, `BackgroundTransparency = 0.34`)
  рисовался, пока `view` не-nil → **съедал каждый клик игры**, включая HUD из другого ScreenGui.

**Триггер.** Открыть и закрыть любой экран CollectorUI **до первого снапшота с сервера**. Навигация
видна с первого кадра, а первый снапшот приходит только после загрузки профиля из DataStore
(0.5–3 с в опубликованном сервере). Клиентский `send("Snapshot")` при старте отбрасывается сервером:
`context.states[player]` ещё нет.

**Замер до исправления** (Studio, реальный модуль `CollectorUI`):

```
[after open, no snapshot]   Navigation=true  ModalBlocker=ABSENT
[after close, no snapshot]   Navigation=ABSENT ModalBlocker=ABSENT
[after snapshot arrives]     Navigation=ABSENT ModalBlocker=true(Modal=true) Window=true
```

A/B на клик (контрольная кнопка в ScreenGui с `DisplayOrder = 25`, ниже CollectorUI):

| Состояние | Клик по блокеру | Клик по контрольной кнопке |
|---|---|---|
| блокер виден | **1** | **0** |
| блокер скрыт | 0 | **1** |

**Исправление.** Три части:

1. `Window` помнит через `React.useRef`, показывалось ли окно хоть раз. Если окно монтируется уже
   закрытым, состояние очищается сразу (`p.Settled()`), а не пружиной: пружина с неизменной целью
   не сообщает о покое. Нормальное закрытие по-прежнему анимируется (`wasVisible.current` → `goal(0)`
   → `onComplete` → `Settled`).
2. `ModalBlocker` создаётся только когда `handle.Active ~= nil` (экран открыт). Модальный блокер
   физически не может пережить закрытие.
3. `handle:close` не чистит `View`: состояние снимает settle-колбэк, иначе пропала бы анимация
   закрытия.

**Замер после исправления** (тот же сценарий, тот же модуль):

```
[A после триггера — открыть/закрыть до 1-го снапшота]  Navigation=true  Blocker=ABSENT
[B экран открыт, данные есть]                          Navigation=true  Blocker=true(Modal=true)  Window=true
[C закрыт]                                             Navigation=true  Blocker=ABSENT
[D второй цикл]                                        Navigation=true  Blocker=ABSENT
```

Модальная эксклюзивность открытого экрана сохранена (шаг B). Живой клик в игре: открытие «Pets»
даёт `blocker=true(Modal=true)`, закрытие «×» убирает блокер и возвращает навигацию; контрольная
кнопка после закрытия получает 1 клик.

## 2. HIGH

### A2. Сбой импорта старого профиля навсегда запирал игрока

- **Где:** `src/server/Services/ProfileService.luau`, `src/shared/Core/ProfileData.luau:112-123`

`assert(not err, err)` превращал два восстановимых случая (`Legacy profile still has an active
session`, `Malformed legacy profile`) в фатальную ошибку: игрок кикался со словами «rejoin shortly»,
старая запись не менялась, и **каждый следующий вход повторял ту же ошибку**. Ошибка чтения
хранилища (`GetAsync` бросает) давала тот же эффект.

Исправлено: чтение старого хранилища обёрнуто в `pcall`, ошибки переноса пропускаются с
предупреждением `[Ball profiles]` (без UserId и ключа хранилища), игрок получает свежий профиль и
играет. Фатальным остался только неизвестный номер версии профиля.

### A3. Продукт `AdminEgg` можно было покупать бесконечно и в обход лимита в 60 питомцев

- **Где:** `src/server/Gameplay/Receipts.luau`

Ветка чека не ставила `perks.AdminEgg`, поэтому защита «Already owned» в `Commands.luau` не срабатывала
никогда, а лимит инвентаря в 60 питомцев не проверялся. Каждая покупка добавляла питомца с
бустом ×25. Исправлено: покупка одноразовая, лимит 60 действует, пропущенная награда всё равно
записывает чек (иначе Roblox повторял бы его бесконечно).

### A4. Флаг загрузки профиля снимался до публикации профиля

- **Где:** `src/server/Services/ProfileService.luau`

Между `self.loading[player] = nil` и `self.profiles[player] = profile` код уступал (`Reconcile`,
`GetAsync`). Второй `Load` того же игрока в это окно запускал второй `StartSessionAsync` →
ProfileStore отвергал его → игрок кикался «Your data could not be loaded», хотя первая загрузка
проходила. Исправлено: флаг держится до публикации профиля и снимается ровно на одном пути выхода.
